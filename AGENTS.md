# AGENTS.md

Last verified: 2026-10-20.

Personal macOS dotfiles. Files in this repo are symlinked into the home directory by Dotbot. Editing a linked file edits the repo.

## Commands

```bash
./install --only link          # Relink files. Use this after link-map changes.
make ssh-key                   # Write ~/.ssh/id_git.pub from the 1Password item "Git".
./git/set-gitconfig.sh         # Rewrite ~/.gitconfig. Personal email, work override for one directory.
make brew-optional             # Prompt before each package in macos/Brewfile.optional.
make brew-dump                 # Write gitignored macos/Brewfile.dump. Not the install list.
```

Run a full install only when the user asks to reinstall the machine:

```bash
./install                      # Full install. See "Install from scratch" before running it.
```

## Critical rules

1. Keep private keys, 1Password items, and shell history out of git. `~/.ssh/id_git` and `~/.zsh_history` stay on the machine.
2. Use one SSH key for GitHub and GitLab. The 1Password item is `Git`. The public file is `~/.ssh/id_git.pub`. Run `make ssh-key` to refresh it.
3. Leave personal commits unsigned. `~/Development/Current/` is the only tree that uses `mistecker@bbw.com` and signs with `~/.ssh/id_git.pub`.
4. Let mise own Node, pnpm, and Python. Versions are in `mise/config.toml`.
5. Keep `zsh/zshrc.zsh` as the only shell rc. It is linked to `~/.zshrc`.
6. Edit `macos/Brewfile` by hand. `make brew` prints that reminder and does not dump or uninstall packages.
7. Commit only when asked. Push only when asked. For either, show the review below and wait for confirmation before `git commit` and again before `git push`.
8. Change only what the task needs. Describe any extra problem and leave it unfixed.

## Use cases

The repo lives at `~/.dotfiles`. Linked files are edited in place: a change to `~/.zshrc` is already a change to `zsh/zshrc.zsh`. `~/.gitconfig` is generated by `./git/set-gitconfig.sh` and is not the file to commit.

### Install from scratch

No clone yet. Xcode Command Line Tools must exist first (`xcode-select --install`) because git comes from them.

```bash
git clone --recursive https://github.com/mikestecker/dotfiles.git ~/.dotfiles
cd ~/.dotfiles
```

Before `./install`, list what it will do and wait for acceptance:

- Init submodules, including `dotbot`, `zsh/oh-my-zsh`, and `zsh/zgenom`.
- Install Homebrew if missing, then the short core package list and `macos/Brewfile`. This does not run `brew bundle cleanup`.
- In an interactive terminal, prompt y/N for each entry in `macos/Brewfile.optional`. A non-interactive run skips those prompts. On a work Mac, answer N unless the user wants that personal app.
- Relink every path in `install.conf.yaml`. A real file is renamed to `*.dotbot-backup.<timestamp>` first. Symlinks are replaced.
- Remove dead symlinks in `~` and `~/bin` that point into this repo. That clean is not recursive.
- Install shared editor extensions, the Operator Mono Nerd Font, Node LTS, latest pnpm, and an extra Node latest. Python 3.13 stays declared in `mise/config.toml`; this install script does not install it.
- Rewrite `~/.gitconfig` from `./git/set-gitconfig.sh` and select the iTerm dynamic profile.

`make macos` is not part of `./install`. Run it only when the user wants Finder, screenshot, and related defaults changed.

After install, sign in to 1Password and unlock the app. The `op` binary is the `1password-cli` cask in `macos/Brewfile`. Settings → Developer → Integrate with 1Password CLI does not install it; turn that on, and turn on Integrate with 1Password SDKs, after the cask is installed. Turn on the SSH agent, leave "Generate SSH config file with bookmarked hosts" off, and run `make ssh-key`. If `op account list` is empty, quit and reopen 1Password. An app that was already running when the cask was installed does not see `op`. Do not run `make ssh-key-create` in that case: a failed lookup would mint a new key.

### Second computer

Use the scratch install. The private key is already the 1Password item `Git`, so `make ssh-key` writes `~/.ssh/id_git.pub` only. Decline optional Homebrew prompts on a work Mac unless the user wants those apps.

### Pull latest and update this Mac

Review before changing the working tree or the home directory.

```bash
cd ~/.dotfiles
git status -sb
git fetch origin
git log --oneline HEAD..origin/main
git diff HEAD...origin/main
```

Stop and show the overlap when the working tree is dirty, or when `main` is both ahead of and behind `origin/main`. `git pull --ff-only` refuses a diverged history. If the branch is only ahead, there is nothing to pull.

Read the commits that would come in before changing the machine:

```bash
git log HEAD..origin/main
```

Each commit body has two sections: "Installing from scratch" and "Updating and syncing". Read both. Follow "Installing from scratch" when this Mac has no clone yet or the user is setting the machine up from nothing. Follow "Updating and syncing" when this repo is already installed and the task is to pull. Those steps name the commands for that change. Use the generic install below only for paths they do not already cover.

When the user accepts a fast-forward:

```bash
git pull --ff-only origin main
git submodule update --init --recursive
```

List the linked paths the pull changed. `./install --only link` relinks the whole map and checks out the recorded `dotbot` submodule. It does not install packages or run the shell steps. Use a full `./install` only when the pull changes `macos/Brewfile`, `mise/config.toml`, extensions, fonts, or `install.conf.yaml` shell steps, and name those steps before running it. That full install includes the optional Homebrew prompts.

### Push this Mac's setup

Review before creating a commit or pushing.

```bash
cd ~/.dotfiles
git status
git diff
git log -8 --oneline
```

Show the diff and a proposed commit message. Leave out private keys, `macos/Brewfile.dump`, `~/.config/1Password/ssh/agent.toml`, shell history, and tokens. Port git-identity edits into `git/set-gitconfig.sh` or `git/work.gitconfig`, not into a copy of `~/.gitconfig`.

The commit body is the note the other computer reads on pull. After the summary, add both sections:

```text
Installing from scratch:
- <command or check for a machine that is not set up yet>

Updating and syncing:
- <command or check for a machine that already has this repo>
```

Name every command that machine should run, including "do not" where a command would mint a key, uninstall packages, or copy a token. If a case needs no command, write "nothing to run."

After the user accepts the diff, commit it. Show `git status` and wait again before `git push`. Never force-push `main`.

### Other cases

- Relink after a link-map edit: `./install --only link`. Show paths that will replace a real file.
- Undo a bad link: the previous real file is `*.dotbot-backup.<timestamp>` next to the symlink. Restore that only when asked.
- Update a submodule (`dotbot`, `zsh/oh-my-zsh`, `zsh/zgenom`): change the gitlink on purpose. Do not commit a dirty submodule worktree.
- macOS system settings: `make macos` changes Finder, screenshots, and related defaults. Run it only when asked.
- Personal Homebrew apps: `make brew-optional`. Do not move those casks into `macos/Brewfile` and do not uninstall packages to match the Brewfile.

## SSH

`ssh/config` is linked to `~/.ssh/config`. Both `github.com` and `gitlab.com` use the 1Password agent socket and `~/.ssh/id_git`, then `~/.ssh/id_git.pub`.

On a new Mac:

1. Install the `1password-cli` cask with the rest of `macos/Brewfile`. Settings → Developer → Integrate with 1Password CLI only connects the app. It does not install `op`.
2. Sign in to 1Password, unlock it, and turn on Settings → Developer → SSH agent, Integrate with 1Password CLI, and Integrate with 1Password SDKs.
3. Leave "Generate SSH config file with bookmarked hosts" off. This repo owns `~/.ssh/config`.
4. If `op account list` is empty, quit and reopen 1Password, then run `op signin`. `make ssh-key` writes `~/.ssh/id_git.pub` from the `Git` item. CLI 2.41 returns that field as one JSON object.
5. Confirm with `ssh-add -l` on the 1Password agent socket. The fingerprint must stay `SHA256:asczVZUH97ABbsIKh/fFq3xe4ticUP7ABw9z0QR5zJc`.

An existing `~/.ssh/id_ed25519` is not this key unless `ssh-keygen -lf` prints that fingerprint. Back it up under `~/.ssh/backup/` and leave it out of `ssh/config`. Do not rename it to `id_git`.

`~/.config/1Password/ssh/agent.toml` is per machine. The Private vault entry already offers `Git`. Do not commit that file.

Create a key with `make ssh-key-create` only when no local `~/.ssh/id_git` exists and no 1Password item named `Git` exists. `gitlab` and `github` arguments are ignored so they cannot create a second key.

- Do not add `nvm`, `rbenv`, Homebrew Python, or a second `~/.zshrc` to `PATH`.
- Do not move personal casks from `macos/Brewfile.optional` into `macos/Brewfile` unless asked.
- Do not put API tokens in `cursor/mcp.json`.

- Do not sync `HISTFILE`. History stays in `~/.zsh_history` on each Mac.

## Anti-patterns

- Run `./install` or `make brew-restore` to test a one-file edit. Relink with `./install --only link` instead.
- Replace `macos/Brewfile` with `brew bundle dump`, or run `brew bundle cleanup`.
- Run `make ssh-key-create` or `op item create --ssh-generate-key` while `~/.ssh/id_git` exists or the 1Password item `Git` exists. That mints a key GitHub and GitLab do not trust.
- Treat Settings → Developer → Integrate with 1Password CLI as the install of `op`. The binary is the `1password-cli` cask.
- Point `ssh/config` at `id_gitlab`, `id_github`, or `id_bbw`.
- Load oh-my-zsh syntax highlighting before other plugins. It stays last in `zsh/zshrc.zsh`.
- Treat `macos/Brewfile.dump` as the package list. It is gitignored.
- Follow the README line that says to set the git email by hand. `./git/set-gitconfig.sh` already sets `mike@stecker.me`.
